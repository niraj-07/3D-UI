# TaskBubble — Hackathon scope

VR selects a CAD component, delegates an adjustment, watches a live desktop proposal, and accepts or rejects it. Desktop provides precise input; VR keeps spatial review and final approval.

## Delivered

- One Robotiq gripper assembly in an inspection workshop.
- Two editable fingertips, each with a stable ID, pivot, local rotation axis, and limits.
- Desktop host and VR client using Unity Netcode.
- Controller or tracked-hand selection and gesture-controlled menus.
- Desktop component close-up, slider, exact angle entry, and Submit.
- Cyan proposal ghost; the real part moves only after acceptance.
- Reject, revise, resubmit, re-delegate accepted parts, and reset the current part.
- Windows PC VR through Quest Link/Air Link. The hand-tracking demo uses the Unity Editor as the VR client.

One task is active at a time. Position editing, unrestricted rotation, runtime CAD import, mechanical joint simulation, and an Android build are outside this version. Current run instructions and limitations are in the [README](../README.md).

## Submission

Repository and a 3–5 minute demonstration video, including an explanation of an important code segment. The judging weights are novelty and technical contribution (35%), technical execution (25%), presentation and clarity (20%), and collaboration and team dynamics (20%).

The [IEEE project notes](PRD_IEEE_VR_2027.md) describe possible follow-up work, separate from this submission.
